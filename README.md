# Sablewisp

> 一个轻量、现代的 Chrome 书签管理扩展（Manifest V3）。
> 帮你的浏览器书签保持整洁、可用：一键检测失效链接、快速搜索、按分组管理、灵活排序、批量导入导出。

> 注：`Sablewisp` 是项目代号，与功能无直接关联；功能介绍见下。

## 简介

Sablewisp 解决的是「书签越攒越多、失效链接难以发现、查找与管理费劲」的日常痛点。它不追求大而全，只聚焦最常用、最实用的几件事：

- 你有没有一群点开却是 404 / 连接超时的书签？Sablewisp 能批量探测并列出「不可达清单」。
- 书签太多、记不住放在哪个文件夹？支持按标题、网址、分组名实时搜索，并可勾选搜索范围。
- 想按文件夹归类查看？弹窗与管理页均按书签分组折叠展示。
- 想快速备份 / 迁移？Netscape 标准格式的批量导入导出，可精确到「指定分组 / 分组内指定书签」。

## 功能

- **有效性检测（本地 + 在线双重）**：对全部 `http(s)` 书签先做本地四重探测（可读状态 GET → favicon.ico 状态探测 → favicon 图片探测 → GET 长超时重试）。由于 manifest 已声明 `host_permissions`，扩展页可读取真实 HTTP 状态码：**收到任何 HTTP 响应即判定本地可达**——包括 Cloudflare 等防护站返回的 403 人机验证、429 限流、503 等响应，防护站不会被误判。本地打不开时，自动改用在线多节点检测工具 **check-host.net**（由后台 Service Worker 发起）验证「全球可达性」。结果区分两类不可达：**网站故障**（全球均不可达）与 **本地访问不可达**（仅本地网络不可达、全球正常）。检测后生成「不可达清单」（可逐个打开 / 删除，支持勾选重检）。
- **搜索**：标题 + 网址 + 分组名实时过滤；弹窗与管理页顶部均提供「标题 / 网址 / 分组」三个范围胶囊，可勾选决定搜索范围。
- **分组管理**：按书签文件夹折叠分组展示；收藏当前页到指定分组（收藏时可搜索分组、可编辑书签标题）。
- **排序**：按添加时间（新→旧 / 旧→新）、网址 A-Z、标题 A-Z。
- **单条检测**：管理页每个书签右侧提供「检测」按钮，可对指定单个网址单独做有效性检测（本地 + 在线双重策略），检测结果实时刷新并同步到不可达清单。
- **批量导入 / 导出**：Netscape 标准书签 HTML 格式，支持导入；导出时可选择「全部书签」或「自定义」（勾选指定分组 / 分组内指定书签），**分组默认折叠**（避免书签过多难以定位），弹窗与管理页选项一致。
- **删除管理**：单条书签编辑 / 删除；主列表每行可勾选，勾选后「已勾选 N 个」选择栏**吸顶悬浮**（长列表滚动到任意位置都可操作），进行自定义批量删除；不可达清单支持勾选批量删除；分组支持一键删除（含其下全部书签，需确认）。
- **浏览辅助**：右下角「↑ 回到顶部 / ↓ 跳到底部」浮动按钮；书签增删改**自动同步**（监听 chrome.bookmarks 变更事件，无需手动刷新）。
- **其它**：打开全部、统计面板、首次使用引导、完整帮助页。

## 安装（开发者模式加载）

1. 打开 `chrome://extensions`
2. 右上角开启「开发者模式」
3. 点击「加载已解压的扩展程序」，选择本仓库目录（含 `manifest.json` 的目录）
4. 固定扩展后点击工具栏图标即可使用

## 文件结构

| 文件 | 作用 |
|------|------|
| `manifest.json` | 扩展清单（bookmarks / storage / tabs 权限 + host_permissions + CSP `connect-src *`） |
| `popup.html / popup.js / popup.css` | 工具栏弹窗：搜索、范围、收藏当前页、导入导出、检测、帮助 |
| `manager.html / manager.js / manager.css` | 完整管理页：分组 / 排序 / 不可达清单勾选重检 / 选择性导出 |
| `common.js` | 共用逻辑：读取扁平化、排序、本地 + 在线混合探测、导入导出 |
| `background.js` | Service Worker：初始化设置存储 + 在线可达性检测消息中枢（check-host.net 多节点 TCP 探测） |
| `help.html` | 完整功能说明页 |
| `icon16/48/128.png` | 图标（由 `generate_icons.py` 生成） |

## 检测原理与局限

有效性检测采用「本地 + 在线」混合策略，目的是在**不误伤本地网络偶发异常**的前提下尽量准确：

1. **本地四重探测**：`GET 可读状态探测（10s）→ favicon.ico 状态探测（8s）→ favicon 图片探测（8s）→ GET 长超时重试（14s）`。manifest 已声明 `host_permissions`，扩展页 fetch 不受 CORS 限制、可读取真实 HTTP 状态码。**收到任何 HTTP 响应（任意状态码）即判定本地可达**——服务器有响应就证明站点在本地网络层可达；Cloudflare 等防护站的 403 人机验证、429 限流、503 响应同样算可达（真实浏览器打开后通过验证即可正常访问），避免防护站被误判为「本地访问不可达」。本地探测**无法识别 HTTP 404 / 500**（有响应即视为存活）。
2. **在线多节点检测**：当本地不可达时，扩展通过**后台 Service Worker** 调用免费检测服务 [check-host.net](https://check-host.net) 的 TCP 检测接口，从多个地理节点（默认 3 个）同时建立 TCP 连接，得出「全球可达性」结论。Service Worker 的 `fetch` 不受扩展页 CORS 限制，因此可读取第三方响应（扩展页直接 `fetch` 会被 CORS 拦截）。
3. **结果标记**：
   - **可达**：本地或在线任一节点能建立连接。
   - **网站故障**：在线多节点**全部**连接失败（全球不可达）→ 站点确实挂了。
   - **本地访问不可达**：本地失败、但在线多节点能连接（仅本地网络/防火墙/地区限制导致打不开）；或在线服务偶发不可用时保守标记。

**局限**：在线检测依赖第三方服务，可能比纯本地检测稍慢，且免费接口存在限流（扩展已内置最小请求间隔与重试做缓解）；极端情况下在线服务不可用会保守标记为「本地访问不可达」。检测结果应作为「疑似失效」参考，而非绝对结论。
